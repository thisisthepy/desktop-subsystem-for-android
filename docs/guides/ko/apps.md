# 앱과 창

Android 앱의 작업은 하나하나 독립된 데스크톱 창으로 열리고, 작업 표시줄 단추도 따로 가집니다. 휴대폰 화면을
통째로 보여 주는 에뮬레이터 창은 없습니다. 이 페이지는 Windows용 Desktop Subsystem for Android™(DSA)를
설명합니다.

## 앱 열기

- **시작 메뉴**: 설치된 앱마다 자기 이름과 아이콘으로 시작 메뉴에 항목이 생기므로 Windows 검색으로도 찾을
  수 있습니다. Android가 실행 중이 아니면 먼저 Android를 시작합니다.
- **DSA 설정**: **앱** 페이지에서 앱 옆의 **열기**를 누릅니다.
- **명령줄**: `dsa apps list`는 설치된 앱과 패키지 이름을 보여 줍니다. `dsa launch <package>`는 앱을
  엽니다. 예: `dsa launch com.android.settings`

다른 프로그램의 시작 메뉴 항목이 이미 같은 이름을 쓰고 있으면, DSA는 이름 뒤에 패키지 이름을 붙입니다. 예:
`Clock (com.example.clock)`. DSA는 자기가 만든 항목만 바꾸거나 지웁니다.

## 앱 창 다루기

- 작업마다 창, 작업 표시줄 단추, Alt+Tab 항목이 따로 있고, 앱의 이름과 아이콘이 표시됩니다. 작업
  관리자에도 앱 이름으로 나타납니다.
- 스냅 레이아웃, Windows 11 제목 표시줄 단추, 실시간 크기 조정을 쓸 수 있습니다. 창 크기를 바꿔도 앱이 다시
  시작되지 않습니다.
- 마우스, 터치, 펜(필압, 지우개, 측면 단추), 키보드를 모두 쓸 수 있습니다. 글자는 한국어를 비롯한 Windows
  입력기로 입력합니다. Android 키보드 앱은 없습니다.
- 내레이터 같은 화면 읽기 프로그램이 UI Automation으로 앱 내용을 읽습니다.
- 창을 닫으면 Android에 그 작업을 끝내도록 요청합니다.

## 앱 창 크기 정하기

DSA 설정의 **앱** 페이지에서 정합니다.

- **크기 조절**을 끄면 앱 창이 열린 크기 그대로 유지됩니다.
- 앱 창이 처음 열리는 크기를 고릅니다. **Android가 정한 크기로 열기**, 또는 휴대폰이나 태블릿의 세로, 가로
  크기 중에서 고를 수 있습니다.

바꾼 설정은 앱이 다음에 여는 창부터 적용됩니다. 명령줄에서는 다음과 같이 합니다.

```
dsa app-window <package> --fixed-size on        # 크기 조정과 최대화를 막습니다
dsa app-window <package> --start-size 1280x800  # 이 크기로 엽니다. auto는 Android가 정합니다
dsa app-window <package> reset                  # 기본값으로 되돌립니다
```

## 알림

Android 알림은 앱 이름과 아이콘이 붙은 Windows 알림으로 나타납니다.

- 알림을 누르면 앱이 열립니다.
- 알림을 닫으면 Android에서도 닫힙니다. 앱이 계속 표시하도록 정한 알림은 예외입니다.
- Android가 Doze 상태여도 알림은 계속 옵니다. [메모리](memory.md)를 참고하십시오.

## 백그라운드에서 실행 중인 앱

음악 재생 앱처럼 창을 닫은 뒤에도 계속 실행되는 앱은 알림 영역에 아이콘으로 나타납니다. 아이콘에 마우스를
올리면 앱의 알림 내용이 보입니다.

- 아이콘을 누르면 앱이 열립니다.
- 마우스 오른쪽 단추로 누르면 **열기**, 알림에 있는 동작, **중지**가 나옵니다.
- **중지**는 먼저 확인을 묻습니다. **다시 묻지 않음**을 선택하면 다음부터 묻지 않습니다. 다시 묻게 하려면
  DSA 설정 **백그라운드에서 실행 중** 페이지에서 **알림 영역에서 앱을 중지하기 전에 묻기**를 켭니다.
- 미디어를 재생하는 앱은 미디어 키와 Windows 미디어 컨트롤로도 조작할 수 있습니다.

DSA 설정의 **백그라운드에서 실행 중** 페이지에 이런 앱이 나열되며, 앱마다 **열기**와 **중지**가 있습니다.
명령줄에서는 `dsa background`, `dsa background open <package>`, `dsa background stop <package>`를
씁니다.

## 바탕 화면 위젯

Android 위젯을 바탕 화면에 독립된 창으로 놓을 수 있습니다. 위젯은 다른 창 아래에 있고, 바탕 화면 보기를
해도 사라지지 않으며, 작업 표시줄과 Alt+Tab에는 나타나지 않습니다.

1. DSA 설정의 **위젯** 페이지를 엽니다.
2. **앱이 제공하는 위젯**에서 원하는 위젯 옆의 **바탕 화면에 추가**를 누릅니다. 앱이 위젯 설정을 요구하면
   설정 창이 열립니다.
3. 위젯을 옮기려면 위젯을 가리킬 때 오른쪽 위 모서리에 나타나는 동그란 **더 보기** 단추를 끕니다.
   위젯의 아무 곳이나 누른 채 0.5초 동안 움직이지 않다가 끌어도 옮겨집니다. 바로 끌면 위젯 자체의
   동작이 되므로 위젯의 목록은 그대로 스크롤됩니다. 가장자리를 끌면 크기가 바뀝니다. 놓은 위치는 DSA가
   기억합니다.
4. **더 보기** 단추를 누르거나 위젯을 마우스 오른쪽 단추로 누르면 **크기 조정**(위젯이 허용하는 크기
   중에서 고르기)과 **제거**가 나옵니다. 이 메뉴에서도 화살표 키, Enter, Esc를 쓸 수 있고, 글자 키로
   항목을 고를 수 있습니다. **크기 조정**은 R, **제거**는 M입니다.

명령줄에서는 `dsa widgets list`, `dsa widgets add <provider>`, `dsa widgets remove <id>`를 씁니다.

## 링크와 클립보드

- Android 앱에서 누른 웹 링크는 Windows의 기본 브라우저에서 열립니다. 설치된 앱이 자기 것으로 확인한
  링크는 그 앱에서 열립니다.
- 모든 웹 링크를 Android 앱에서 열려면 DSA 설정 **고급** 페이지에서 **안드로이드 앱에서 웹 링크 열기**를
  켭니다(`dsa settings set links-in-android on`).
- 복사한 텍스트는 Windows와 Android 사이에서 양쪽으로 공유됩니다. 끄려면 **고급** 페이지에서
  **안드로이드와 클립보드 공유**를 끕니다(`dsa settings set clipboard off`).

## ARM 전용 앱

x64 PC에서 ARM 프로세서용 코드만 있는 앱은 ARM 번역기를 거쳐 실행됩니다. x64 PC의 Android에는 오픈 소스
번역기 Digitalis가 함께 들어 있고, 처음 시작할 때부터 이것을 씁니다. 다른 번역기를 대신 쓸 수도 있습니다.

- **Google의 ARM 번역기.** **고급** 페이지의 **Google의 ARM 번역기** 옆 **받기**를 선택하거나
  `dsa arm-translation fetch google`을 실행합니다. DSA가 먼저 출처와 Google의 약관
  ([Android SDK 라이선스](https://developer.android.com/studio/terms))을 보여 주며, 동의하기 전에는
  아무것도 받지 않습니다. 그다음 PC가 Google이 이 Android 버전용으로 제공하는 Android 에뮬레이터
  이미지(약 2GB)를 받아 번역기만 남기고 나머지는 지웁니다. DSA는 Google의 번역기를 싣거나 다시
  배포하지 않습니다.
- **직접 만들거나 따로 구한 패키지.** 오픈 소스 번역기 Digitalis로 만든 패키지 같은 것입니다:
  `dsa arm-translation install <folder>`

그다음 Android를 다시 시작합니다. DSA 설정 **일반** 페이지에서 Android를 종료한 다음 앱을 엽니다.

Android에 함께 들어 있는 번역기로 돌아가려면 **고급** 페이지의 **기본 번역기 사용** 옆 **사용**을
선택하거나 `dsa arm-translation use-default`를 실행합니다. 설치한 묶음을 지우며, 다음에 Android를
시작할 때부터 적용됩니다.

Android가 쓰는 번역기는 `dsa arm-translation status`로 확인합니다. **고급** 페이지의 **ARM 전용 앱 실행**
스위치는 아무것도 지우지 않고 번역을 켜거나 끕니다. 64비트 ARM 앱(`arm64-v8a`)만 실행할 수 있습니다.
ARM64 PC에서는 Android가 ARM 앱을 직접 실행하므로 번역기가 필요 없습니다.
